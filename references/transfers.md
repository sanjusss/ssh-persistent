# 文件传输

上传或下载文件时读取。`S` 指向技能目录中的 `ssh-mux.sh`，主机别名均为示例。

```bash
$S push A ./app.tar.gz /tmp/   # 上传文件
$S pull B /var/log/app.log ./  # 下载文件
```

## 选择传输方式

`push` 和 `pull` 支持 `--session`、`--timeout` 和 `--transport`，这些选项可放在别名或路径的前后。

| `--transport` | 行为 |
| --- | --- |
| `auto` | `jump` 使用 SSH 二进制流；`shell` 探测 Base64 工具，不可用时采用八进制上传、十六进制下载。 |
| `stream` | 通过 `ssh -T` 直接传输二进制，仅适用于 `jump`。 |
| `base64` | 分块编码传输；依次探测原生 `base64`、`OpenSSL`、Python 3，没有可用工具时报错。 |
| `octal` | 上传使用 shell 的 `printf` 八进制转义；下载使用 `od` 十六进制输出。 |
| `scp`（默认） | 使用原有的传统 `SCP` 协议，见下节。 |
| `hybrid` | 多级路径按段选择方式；每个远端段由外层主机上的临时脚本直接执行。 |

```bash
"$S" push A ./archive.bin /tmp/ --transport base64
"$S" pull A /tmp/archive.bin ./ --transport octal --session case-1234
"$S" push A ./archive.bin /tmp/ --transport scp
```

**默认仍使用原有的 `scp` 方式。** 无 `scp` 时，请显式指定 `--transport auto`、`stream`、`base64` 或 `octal`。编码数据沿已登录的终端直接到达目标主机；不需要 `[local]`、本机 SSH 服务或暂存主机，也不要求中转机安装编码工具。

### 依赖与文件行为

新方式支持单个普通文件，包括空文件和任意二进制内容。目标为已有目录时保留文件名；路径中的中文、空格、引号和 shell 特殊字符按字面处理。不支持目录递归、文件符号链接、带控制字符的路径或波浪号展开；请使用绝对路径或相对当前远端目录的路径。

远端需要基本的 `POSIX` shell 与 `cat`、`wc`、`mkdir`、`mv`、`rm`；编码传输还需要 `dd`。必须提供一个可用的 `SHA-256` 工具（计算文件摘要，用来核对内容）：`sha256sum`、`shasum`、`openssl` 或 `python3`。脚本会实际验证编码与校验工具，不会自动安装依赖。

上传先写目标目录内的私有临时目录；下载先写本地目标目录内的临时文件。总字节数和 `SHA-256` 摘要一致后才替换目标文件，传输或校验失败时保留原文件。下载还会重新核对源文件摘要；需要快照一致性时，请先在远端生成固定副本。

新生成的目标文件权限为 `600`，只传输内容和文件名，不保留原权限、所有者或时间戳。上传需要目标所在目录可写；覆盖目标也会生成新文件，原有硬链接继续指向旧文件。请勿在传输期间并发修改同一源文件或目标路径。

分块上传按固定偏移覆盖，终端断线后重试同一命令不会重复追加内容；不提供跨进程断点续传。SSH 二进制流中断会报错，可重新运行整次传输。

成功、失败或键盘中断时都会尝试清理临时文件。若连接无法恢复，会报告残留目录，请恢复连接后删除。传输结束不会关闭共享连接。

### 超时与速度

新方式的 `--timeout` 默认为 3600 秒，须大于 0，上限为 7200 秒；用于整个传输过程中的探测、分块和校验。登录、断线重建、终端恢复及失败清理可能增加实际等待时间；清理命令另有 15 秒执行额度。

Base64 上传每块最多 1024 字节，八进制上传最多 256 字节；路径较长时自动减小。下载每块最多 32768 字节。终端每块都需等待确认，大文件速度主要受网络往返延迟限制。选择新方式时，直连可使用 `--transport stream` 传输二进制流。

Base64 不提供额外保密性，数据依靠 SSH 加密。堡垒机终端审计与调试日志可能保留编码后的内容。设计依据和此前原型测量见[替代传输方案研究](no-scp-transfer.md)。

多级跳板按段选择方式时，使用 `--transport hybrid`，详见[混合传输](hybrid-transfers.md)。其余方式仍作用于整次操作。

## 使用默认的 `SCP`

`--transport scp` 使用传统的 `SCP` 文件复制协议。新版 `scp` 自动添加 `-O`，不支持该选项的旧版使用默认协议。传输两端都需要提供 `scp`；仅提供 `SFTP` 子系统的账号不适用。

`jump` 模式共用已建立的 SSH 连接，并忽略 `--session` 和 `--timeout`。`shell` 模式的 `--timeout` 表示每两台主机之间的传输超时，默认为 3600 秒，上限为 7200 秒。

`shell` 模式经中转主机逐台运行 `scp`。路径中的空格和引号按文件名处理，目标为已有目录时保留文件名。这种方式需要配置 `[local]`，下面两种方式选一种。

### 本机可以接受 SSH 登录

本机运行 `sshd`（接收 SSH 登录的服务）时，在 `[local]` 中填写本机地址和登录信息：

```bash
$S host add local --host 1.1.1.1 --user myuser --password 'xxx'
```

地址必须能被中转主机访问，不能填写 `127.0.0.1`。中转主机通过 `scp` 从本机读取文件，或把文件写回本机。这种传输方式需要配置本机的登录密码。

### 本机不能接受 SSH 登录

用 `staging` 指定一台暂存主机。本机和连接路径上的第一台中转主机都必须能通过 SSH 登录这台服务器。

```bash
$S host add relay --host 5.5.5.5 --user root --password 'xxx'
$S host add local --staging relay
```

上传时，本机先上传到暂存主机，中转主机再从那里取文件。下载时，中转主机先上传到暂存主机，本机再下载。

暂存主机必须使用 `jump` 模式，可以经过标准跳板机访问，并且必须配置 `password`。使用 `staging` 后，`[local]` 的 `host`、`user`、`password` 可以省略。如果已有 `[local]`，先删除再按所选方式添加。

每次在中转主机上复制文件时，脚本优先使用那台主机上的 `sshpass` 填写密码。没有 `sshpass` 时，脚本会尝试识别密码提示并应答。如果输出中恰好出现 `password:`，可能被误认为密码提示。

使用 `sshpass` 时，密码通过 `SSHPASS` 环境变量传递。有权读取中转进程环境的用户仍能看到密码。发送的命令包含密码，只有中转 shell 启用了 `HISTCONTROL=ignorespace` 时，行首空格才会阻止命令写入历史。相邻两跳使用不同密码时，请评估这些影响是否可接受。
