# 多级跳板混合传输设计

状态：早期设计记录。`hybrid`、`--leg`、`--plan` 已实现，当前用法和限制见[混合传输](hybrid-transfers.md)。

后续设计已改为在连接发起端运行临时脚本，远端文件内容不经本机中转。自动重试失败段和跨段优化仍未实现。

现有默认 `scp` 和显式 `auto`、`stream`、`base64`、`octal` 保持原有含义。实现本设计时，只有选择 `--transport hybrid` 才进入新的规划与执行流程。

## 1. 范围与原则

支持单个普通文件，在不同传输段选择不同方式。例如第一段沿堡垒机终端传送 Base64，后续段在内网运行 `scp`。不增加目录递归、权限复制或跨进程断点续传。

区分三种路径：

- 登录路径：如何从本机登录目标，由现有 `via` 和堡垒机路由配置决定。
- 控制路径：本机通过哪个会话，在哪台主机执行复制、校验和清理命令。
- 文件路径：文件内容实际经过哪些连接，在哪些主机保存完整副本。

计划必须同时列出这三种信息。登录经过一台跳板，不代表需要在该跳板落盘。标准 SSH 转发节点和仅提供用户名路由的堡垒机都可以只转发连接。

这里的“协议”包含现有参数中的几种传输方式。Base64、八进制本身只是编码，仍通过 SSH 终端传递。

## 2. 命令接口

```bash
# 当前接口用法和限制见混合传输说明
"$S" push T ./archive.bin /srv/archive.bin --transport hybrid --plan
"$S" push T ./archive.bin /srv/archive.bin --transport hybrid

# 固定部分传输段，未指定的部分由规划器选择
"$S" push T ./archive.bin /srv/archive.bin --transport hybrid \
    --leg '@local:A=base64' --leg 'A:B=scp' --leg 'B:T=stream'

# 下载仍用从外到内的连接对命名，避免反转连接发起方
"$S" pull T /srv/archive.bin ./archive.bin --transport hybrid \
    --leg '@local:A=base64' --leg 'A:B=scp' --leg 'B:T=stream'
```

`@local` 表示执行工具的本机，与配置中用于反向 SSH 登录的 `[local]` 分开。

`--leg A:B=scp` 指定外层端点 `A` 与内层端点 `B` 之间的方式。上传时内容从 `A` 到 `B`，下载时从 `B` 到 `A`；连接通常都由 `A` 发起。端点使用配置别名，不使用易随配置变化的数字序号。

首版只允许指定去除路由型堡垒机后的相邻端点。显式指定的段不能被合并或换成另一协议。重复指定、未知端点、不相邻端点或能力不满足时直接报错。

`--plan` 生成计划后退出，不传送用户文件，不修改最终目标。能力验证可以登录，并创建少量私有测试文件；结束前清理。计划输出不含密码、完整认证命令或文件内容。正常执行也先生成并输出同样的计划。

首版不将计划保存为可执行文件。执行时重新验证能力，避免使用过期连接状态或旧临时路径。

## 3. 一个完整例子

假设配置中的登录路径如下，`R` 只负责用户名路由：

```text
本机 L → 堡垒机 R → A → B → T
```

能力假设：本机到 `A` 只能使用终端；`A`、`B` 支持传统 `SCP`；`B` 到 `T` 支持无终端 SSH 命令，但 `T` 没有 `scp`。

### 上传计划

| 段 | 文件流向 | 执行位置与连接发起方 | 方式 | 完整副本位置 |
| --- | --- | --- | --- | --- |
| 1 | `L` → `A` | `L` 控制穿过 `R`、已经登录 `A` 的终端 | Base64 | `A` 的私有临时目录 |
| 2 | `A` → `B` | `L` 控制 `A`；`A` 主动连接 `B` | `scp` | `B` 的私有临时目录 |
| 3 | `B` → `T` | `L` 控制 `B`；`B` 主动连接 `T` | `stream` | `T` 的目标目录内临时文件 |

第 3 段的数据在 `B` 的文件描述符和 `B`→`T` 的 SSH 标准输入之间传递。原始文件字节不进入本机控制 `B` 的终端。

### 下载计划

| 段 | 文件流向 | 执行位置与连接发起方 | 方式 | 完整副本位置 |
| --- | --- | --- | --- | --- |
| 1 | `T` → `B` | `L` 控制 `B`；`B` 主动连接 `T` 读取文件 | `stream` | `B` 的私有临时目录 |
| 2 | `B` → `A` | `L` 控制 `A`；`A` 主动从 `B` 下载 | `scp` | `A` 的私有临时目录 |
| 3 | `A` → `L` | `L` 通过 `A` 的终端读取编码块 | Base64 | `L` 的目标目录内临时文件 |

上传、下载都不需要 `A` 登录 `L`，不依赖 `[local]`。`R` 不保存文件副本。每一段完整校验通过后才启动下一段。

## 4. 能力探测与选择

### 能力必须按连接方向记录

“`B` 装有 `scp`”不足以证明 `A`→`B` 可以传文件。需要确认 `A` 能从自己的网络位置连接 `B`，并且账号允许相应操作。

| 能力记录 | 检查内容 |
| --- | --- |
| 主机文件操作 | 普通文件读写、私有临时目录、长度与 `SHA-256` 摘要工具 |
| `A` 发起连接到 `B` | 配置的地址、端口、路由和认证是否可用 |
| `A`→`B` 的 `scp` | 两端工具、传统协议选项，以及小文件的真实往返 |
| `A`→`B` 的 `stream` | 无终端命令执行、标准输入输出、任意字节样本往返 |
| 终端编码 | 对应端点的编码、解码与固定偏移写入是否可用 |
| 暂存条件 | 指定目录可写、空间估计与实际写入结果 |

不按文件扩展名猜测协议。能力探测结果仅在本次任务内使用，并绑定完整连接身份。连接重建后使相关结果失效；不只按目标 IP 缓存。

`SHA-256` 是用于核对文件内容的摘要。没有可靠校验工具时，该端点不能作为混合传输的文件暂存点或最终端点。

### 首版选择规则

1. 检查完整登录链，保留所有转发和认证信息。不能只调用当前的 `host_mode(target)` 判断整条链。
2. 从文件端点列表去掉只提供路由、无法保存文件的堡垒机。
3. 全链为标准跳板且没有显式分段时，合并为 `L` 与最终目标的一段。中间主机只转发连接。
4. 含终端登录限制时，首版按可执行文件操作的相邻端点分段。暂不自动合并远端发起的多级 SSH 转发。
5. 每段遵守 `--leg`；未指定的段依次考虑直接 `scp`、直接 `stream`、终端 Base64、终端八进制方案。
6. 已配置的 `[local]` 或 `staging` 可以提供额外的 `SCP` 候选路径。仅使用已有配置，不猜测本机可回连地址或新增服务器。
7. 排除无法建立控制会话、无法校验或没有可写暂存位置的方案。没有完整可执行路径时，在传输用户文件前报错。

“直接”表示两端之间传文件，即使建立连接需要标准跳板，也不经过本机应用层读取再写回。协议优先级是首版的确定性策略，不代表对所有网络都最快。计划应报告暂存次数和经过本机的终端编码段，不承诺最短耗时。

一次任务内，每个候选方式只探测一次。工具或协议明确不支持时继续检查下一候选；认证失败、主机身份不匹配、权限不足和磁盘写入失败直接报告。不能将所有非零退出码都解释为“协议不可用”。

## 5. 只有终端的一段如何传输

文件位于 `B`、`B` 到 `T` 只能交互登录时，在 `B` 上部署临时 Python 执行器。

```text
本机 → 任务参数 → B 上的执行器
B 的文件 → B 控制的 SSH 终端 → T 的临时文件
本机 ← 状态和校验结果 ← B 上的执行器
```

执行器读取 `B` 的文件，编码分块并等待 `T` 确认。下载时由执行器接收 `T` 的编码输出，解码到 `B` 的临时文件。原始文件内容和编码块都不返回本机。

当前实现将 `ssh_worker.py`、`ssh_pty.py` 和 `ssh_transfer.py` 打包部署，支持远端 Python 3.4 及更新版本。执行器在任务目录内使用文件锁，防止启动命令被重发后重复传输。运行结果写入结构化文件，供本机查询。

执行端缺少依赖时直接报错，不自动安装软件，也不自动改成本机中转。首版按段完成传输；跨段同时传送数据留作后续优化。

## 6. 会话、认证与进程

### 独立控制各端点

当前嵌套登录使用 `exec ssh`，终端登录到 `T` 后无法返回 `B`。混合传输需要能独立控制保存文件的各端点。

- 通过完整登录路径，为必要端点建立独立控制会话。
- 会话名由任务标识和端点身份生成，满足当前 32 字符限制。
- 尽量只保持当前段所需的两个端点会话。公共标准 SSH 连接可以复用，任务结束只关闭自己创建的终端或远端连接。
- 堡垒机并发限制导致无法同时控制两个端点时，该方案不可用。计划阶段报告，不能在同一持久终端里反复 `exit` 切换主机。
- 传输期间锁定本任务的段操作，避免校验、覆盖和清理并发执行。不同任务使用不同临时目录与会话。

### 远端发起的 SSH

`stream` 在远端执行时，文件重定向必须位于发起连接的主机上。上传是“读取源文件，送入 SSH 标准输入”，下载是“SSH 标准输出写入临时文件”。控制终端只返回完成状态和摘要。

优先使用发起端已有且已授权的认证能力。需要密码时，由本机读取现有配置，在建立这一段连接时提供。不得把本机私钥复制到跳板机。

远端密码认证可能使用 `sshpass -e`，也可能需要先交互认证、再复用单独的连接。后一种方式必须实测在控制终端中断后连接和传输进程的行为。首版未验证的认证组合标记为不支持，不能退回到在命令参数中明文放密码。

沿用明确的主机身份验证配置，不能为探测或回退自动关闭验证。调试输出隐藏认证命令；终端审计仍可能记录命令和编码内容。

## 7. 校验、提交与失败处理

### 每段状态

```text
等待 → 创建临时文件 → 传输 → 校验 → 本段完成
                                      ↓ 最后一段
                              替换最终目标 → 清理
```

本机协调器在开始前读取原始源文件的字节数和摘要。所有中转副本都与这份原始摘要比较，不能只与上一跳的即时摘要比较。

中转目录权限为 `700`，数据文件为 `600`。最后一段的临时文件位于最终目标所在文件系统；全部校验通过后才改名替换。提交前对原始源文件再检查一次，发现变化则中止提交。需要快照一致性时仍需先生成固定源文件。

接入混合模式的 `scp` 也只能写临时文件，再独立校验。旧函数直接写最终目标的行为不能原样复用。

上一段的完整副本保留到当前段校验通过。通过后可以删除更早的副本。失败时默认清理本次任务的副本；首版不提供跨进程恢复。不能删除用户源文件或其他任务的目录。

### 重试与回退

- 固定偏移的编码块允许重发。复制整段时从空的本段临时文件重新开始。
- 每段最多一次连接恢复与重试，并受整次任务的剩余时间约束。
- 先确认前一个传输进程已结束，再重写临时文件。若断线后无法确认，停止该段；不能让两个进程同时写入同一路径。
- 已验证的暂存副本可在本次进程内复用，校验后从当前失败段重试，无需重传前面所有段。
- 运行中不自动更换已选择的协议。能力变化时重新生成计划；避免传输失败后反复登录或不断尝试不同协议。
- 最终改名的回复丢失时，使用本任务标识、临时文件状态和最终文件摘要确认结果。仍无法确认时报告“结果未知”，不能直接宣告失败且目标未变。

当前 `do_exec()` 会在断线后自动重发命令。混合执行器需提供可关闭隐式重发的调用方式，统一计数和处理重试。单纯给现有 `xfer_leg()` 再套一层重试会造成重复执行。

整次任务共用一个截止时间，覆盖探测、登录、传输、校验和正常重试。底层登录、终端恢复也必须接收剩余时间。清理另设明确的小额时间上限；不能对每一跳重新发放完整 `--timeout`。

连接不可用时，清理可能失败。记录本任务未清理的主机别名和精确目录，输出到本机私有诊断信息。不能静默忽略，也不能在未确认归属的目录上执行批量清理。

## 8. 代码划分

以下为拟新增接口，名称可在实现时调整：

| 部件 | 职责 |
| --- | --- |
| `Endpoint` | 本机或远端文件操作；独立控制会话、元数据、临时目录、改名和清理 |
| `CapabilityProbe` | 验证主机工具和有方向的连接能力，保留失败类别 |
| `TransferPlan` | 连接路径、文件流向、协议、发起端、暂存点及本机转发说明 |
| `ScpLeg` | 在指定发起端执行 `SCP`，输出只进入临时文件 |
| `StreamLeg` | 连接源文件描述符与无终端 SSH 的输入输出 |
| `EncodedLeg` | 本机与远端编码传输，或两个远端经本机内存转发 |
| `TransferCoordinator` | 整次任务的时间、状态、校验、有限重试和清理 |

可复用 `ssh_transfer.py` 的编码探测、固定偏移写入和摘要解析。需要将其文件读写抽象为端点操作；不能假设每段至少一端是本地文件对象。

可复用 `build_chain()` 的循环检测、连接身份计算和 `shell_hops()` 的路由过滤。混合规划器单独解释整条链；现有 `jump_connect()` 拒绝“前面是终端、后面配置 `jump`”的组合，不能据此认定内网 `A`→`B` 不支持无终端连接。

现有 `xfer_leg()` 把所有非零结果合并为失败，并忽略部分清理错误。新模式需要结构化结果，区分能力不可用、认证失败、传输失败、校验失败和完成状态未知。

## 9. 分阶段实现与验收

### 第一阶段：规划与逐段复制

实现显式 `hybrid`、计划输出、端点能力探测与固定协议分段。支持本机终端编码进入第一台内网主机，后续用 `SCP` 或二进制流；下载按相反文件流向执行。先把整次校验、最终提交、进程归属和失败清理做完整。

### 第二阶段：两个远端之间的终端编码

由外层主机上的临时执行器直接控制下一跳终端，验证不同编码组合、重复块、任务锁和连接状态。文件内容不经本机中转。

### 第三阶段：减少中转

评估合并远端发起的标准跳板链。仅在能力和收益可测量时增加跨段流水传输；首版逐段完成，无需同时控制多段的缓存和失败状态。

### 必须覆盖的测试

- 旧命令未指定 `--transport` 时，上传和下载仍走原 `SCP` 流程；原 `auto` 含义不变。
- 全标准跳板没有中间落盘；路由型堡垒机不会被当作可读写文件的主机。
- 终端 Base64 → `SCP` → 二进制流的上传，以及连接发起方向不变的下载。
- 两端没有 `scp`、仅提供不同编码工具、缺少校验工具、目标目录不可写。
- 本机没有 SSH 服务且无 `[local]` 时，仍能用终端编码进入内网。
- 显式协议不可用时停止；认证失败不触发协议轮流尝试。
- 空文件、任意字节、特殊文件名、多块文件、重复写入和中途源文件变化。
- 第二段失败，最终目标不变；本次进程内重试只重传第二段。
- 断线但旧传输进程仍在运行时，不启动同路径的第二个写入进程。
- 最终改名成功但回复丢失，能够确认成功或明确报告结果未知。
- 两个任务并发、堡垒机会话数受限、超时耗尽、清理失败和用户中断。
- 本地测试使用虚构配置；真实连接测试脚本和诊断记录保存在仓库外。

当前已有的无 `SCP` 单段测试，只证明现有单段实现可用，不能作为混合传输已通过验证的证据。
