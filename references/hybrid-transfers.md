# 多级跳板混合传输

需要不同传输段采用不同方式时，显式使用 `--transport hybrid`。不指定时仍使用原有 `scp`；`auto` 仍是原来的单段自动选择。

## 使用方式

以下别名均为示例。登录路径为“本机 → 路由型堡垒机 → `A` → `B` → `T`”：

```bash
# 探测各段能力并显示计划；不传输用户文件
"$S" push T ./archive.bin /srv/archive.bin --transport hybrid --plan

# 第一段穿过堡垒机终端，后两段由内网主机直接执行
"$S" push T ./archive.bin /srv/archive.bin --transport hybrid \
  --leg '@local:A=base64' --leg 'A:B=scp' --leg 'B:T=stream'

# 下载仍使用从外到内的端点对命名
"$S" pull T /srv/archive.bin ./archive.bin --transport hybrid \
  --leg '@local:A=base64' --leg 'A:B=scp' --leg 'B:T=octal'
```

`@local` 指运行工具的本机，与反向 SSH 登录配置 `[local]` 分开。`--leg` 可以重复出现，也支持 `--leg=A:B=scp`。仅允许登录链中相邻的文件端点，不包含只提供用户名路由的堡垒机。

每段可指定 `auto`、`scp`、`stream`、`base64` 或 `octal`。未知端点、重复指定或指定方式不可用时报错。`--leg` 和 `--plan` 必须与 `--transport hybrid` 一起使用。

没有显式分段且全链都是标准跳板时，合并为本机与目标之间的一段。含终端限制时按可操作文件的主机分段。首个端点选择终端编码时，无需本机 SSH 服务或 `[local]`。

## 文件实际经过哪里

以“本机 → `A`：Base64，`A` → `B`：`SCP`，`B` → `T`：二进制流”为例：

| 方向 | 文件路径 | SSH 连接发起方 |
| --- | --- | --- |
| 上传 | 本机 → `A` 临时文件 → `B` 临时文件 → `T` 目标 | 本机、`A`、`B` |
| 下载 | `T` → `B` 临时文件 → `A` 临时文件 → 本机 | `B`、`A`、本机 |

工具在每段的外层主机部署一个临时 Python 执行器。执行器直接登录下一跳，完成复制和校验。本机只发送任务参数、查询结果；远端段的文件内容不绕回本机。

下一跳只允许交互终端时，执行器在所在主机控制伪终端，完成 Base64 或八进制分块传输。下载的 `octal` 方式使用 `od` 十六进制输出。本机不承担远端段的数据转发。

## 依赖和认证

- 本机依赖与技能入口相同；远端执行器支持 Python 3.4 或更新版本，需要标准库的 `pty`、`fcntl` 和 `zlib`。
- 只有运行执行器的外层主机需要 Python。最终目标只需文件操作、所选协议和摘要工具。
- 每个保存文件的端点都需要可用的 `SHA-256` 工具，用文件摘要验证内容。
- `SCP` 需要两端提供传统协议工具；二进制流需要下一跳允许无终端 SSH 命令。
- 首版远端执行器先建立一个独占的交互 SSH 会话，用于探测、文件操作和终端编码。仅提供文件子系统、完全不允许 shell 的账号不适用。

执行器使用发起端已有的密钥认证能力，或配置中的下一跳密码。不会复制本机私钥，不安装软件。远端首次连接按首次使用信任方式记录主机密钥，已有密钥变化时拒绝连接。

密码只放在私有任务请求文件中，执行器获得任务锁后读取并删除该文件。部署和认证过程仍可能被堡垒机审计记录；编码不提供额外保密性。

每个必要端点有独立控制会话，远端执行器另建下一跳连接。堡垒机或服务器的并发会话限制可能使计划无法执行。`hybrid` 使用自动生成的任务会话名，忽略用户提供的 `--session`，结束后仅关闭本任务创建的会话。

## 计划与协议探测

`--plan` 会登录服务器、上传执行器和少量测试文件，结束时清理。上传计划会读取本地源文件的长度和摘要；下载计划会读取远端源文件。不会复制用户文件到中转点或替换最终目标。

远端未固定协议时，先检查 `SCP`，再检查无终端二进制流，最后选择终端编码。明确缺少工具或服务器明确拒绝相应命令通道时才继续检查。认证、身份验证、权限或未知传输错误会停止，不将所有错误都解释成协议不支持。

首段使用任意字节样本往返验证所选方式，包括 `SCP` 的反向连接和暂存路径。远端段的 `SCP` 和二进制流同样进行样本往返；终端编解码使用已知样本验证。计划只描述本次探测结果；实际传输前会再次检查远端段的连接与协议。

## 完整性和任务生命周期

各端点使用权限为 `700` 的独立临时目录，传输数据文件权限为 `600`。每段都与原始源文件的字节数和摘要比较。最终临时文件位于目标文件系统，全部校验通过后才替换目标。

只支持单个普通文件，不保留原权限、所有者或时间戳。最终文件权限为 `600`。不支持符号链接、目录递归和路径控制字符。相对远端路径按目标控制会话的当前目录解析，不展开 `~`。

同一个远端任务只能持有一把文件锁。启动命令被重发时，第二个执行器不会再次复制；已有最终结果时直接复用结果。本机断线不代表远端任务已经停止，恢复后先查询同一个任务的结果。

执行过程中出现传输失败时，当前版本停止整次操作，不自动重跑失败段，也不提供跨进程断点续传。重新运行命令会创建新任务与新临时路径。终端控制命令的安全重发和编码块固定偏移覆盖仍然有效。

`--timeout` 默认为 3600 秒，上限为 7200 秒，用于整次规划、登录、部署、传输与校验。远端执行器结束传输后，另给下一跳临时目录清理最多 15 秒；即使传输已超时，仍会尝试恢复终端并清理。本机退出时另给协调清理最多 30 秒，先请求所有远端执行器停止，确认最终状态后才删除中转文件。

无法确认执行器状态时保留本次任务的临时目录，并报告主机别名和精确路径。下一跳目录删除失败时，执行器将残留路径写入结构化结果，本机在删除执行器日志前显示这些路径。应先确认任务结束，再删除目录。正常结束会清理部署包、任务请求、结果和中转文件。

## 实现文件

| 文件 | 职责 |
| --- | --- |
| `ssh_hybrid.py` | 路径规划、执行器部署、任务查询、分段校验及最终提交 |
| `ssh_worker.py` | 在远端主机直接执行到下一跳的传输，处理锁、取消及结构化结果 |
| `ssh_pty.py` | 本机和远端共用的终端登录与命令执行 |
| `ssh_transfer.py` | 编码、固定偏移写入、长度和摘要校验 |
